# Debrief: from is the past, to is the future

A `moved` block is a statement for Terraform's planner: "the object that used to be at `from` is now
at `to`". It is evaluated against the prior state. Terraform looks up `from` in state, finds the
entry, and rewrites the address to `to` before it compares the configuration with reality.

Because `to` must be a declared resource, and `from` must not be, Terraform can detect a mistake. If
`from` is still declared, as here, the block says something impossible, so you get "Moved object
still exists". If neither exists you would see no error, only a destroy and a create, so a swap that
points both at declared names is dangerous in the other direction as well.

The master key is a perfect example of why moves matter. A `tls_private_key` regenerated by accident
cuts every new copy with a different pattern; every lock keyed to the old one no longer matches. The fingerprint recorded in
the register is what the validator watches.

Real-world takeaway: write the move block before renaming anything, read it aloud as
"from the old name to the new name", and look for the line `has moved to` in the plan before applying.
Keep the block for at least one release so every environment sees it.
